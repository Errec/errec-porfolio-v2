# Contributing Guide

Thanks for contributing to this portfolio project.

## Development workflow
- Create a feature branch from the active default branch.
- Keep changes focused to one roadmap task or bugfix at a time.
- Prefer updating source files under `src/` and regenerate production artifacts via build scripts.

## Project structure
- `src/html/index.html`: human-readable homepage source.
- `src/css/main.css`: human-readable stylesheet source.
- `src/js/main.js`: source JavaScript.
- `index.html`, `css/main.min.css`, `js/bundle.min.js`: production artifacts generated by build scripts.
- `scripts/`: build and quality automation scripts.

## Commands to run before opening a PR
- `npm run build`
- `npm test`
- `npm run check:a11y:ci`
- `npm run check:format`
- `npm run lint`

## Style and naming
- Follow `.editorconfig` defaults (UTF-8, LF, no trailing whitespace, final newline).
- Use descriptive class/function names over abbreviations.
- Prefer reusable CSS classes over one-off selectors.
- Keep accessibility attributes (`aria-*`, labels, landmarks) intact when editing markup.

## Review checklist
Before requesting review, confirm:
- [ ] Build artifacts are regenerated when source files changed.
- [ ] Accessibility checks pass (`check:a11y:ci`).
- [ ] Formatting and lint checks pass.
- [ ] Tests pass (or clearly document why not).
- [ ] Roadmap/task docs are updated if task status changed.
